# 智能家电售后服务 Agent 系统 · 需求决策记录

下表记录产品负责人在需求访谈中已确认的决定，作为 PRD 评审与后续 Spec 的业务依据。验收场景编号及待评审假设见 [PRD](../PRD.md)，术语见[领域术语表](../GLOSSARY.md)。

| 编号 | 已确认的决定 | 决策依据或业务影响 |
|---|---|---|
| D-01 | 第一个项目仅占 Day 1～2，包含需求、设计、编码、测试、验收。 | Day 3～4 和 Day 5 分别留给 ETL-Agent 与 NL2SQL 微调。 |
| D-02 | 首版服务已登录且在平台有购买记录的消费者，仅可查询或报修本人设备。设备不明时不判断保修，缺记录或线下购机提示人工核验。 | 确认服务对象和归属是自动保修判断与报修的前提。 |
| D-03 | 每台已购家电预置唯一 DEMO 序列号。多候选时询问选择，同款多台对照机身标签，无法辨认则人工核验。 | 单靠型号或订单项不能定位同一订单项中的某台设备。 |
| D-04 | 首版使用 DEMO 洗衣机和 DEMO 空调。允许同一故障码在不同型号有不同含义；资料带型号和来源，所有虚构数据标注 DEMO。 | 按具体型号、故障码与相关片段查找适用依据。 |
| D-05 | 洗衣机整机保修 12 个月，空调整机保修 24 个月。使用结构化业务政策，从签收日开始计算，满规定月数当天起过保。 | 2025 年 6 月 15 日签收的洗衣机至 2026 年 6 月 14 日仍在保。模型负责解释后端结果。 |
| D-06 | 本人设备缺少签收日时标记「待核验」，允许报修。预览显示「签收日期缺失，保修资格待人工核验」。 | 设备归属与保修资格可分别确认。 |
| D-07 | 已过保仍允许报修。预览显示「已过保，维修费用待人工确认」。模型不得自行生成维修费用。 | 消费者可在了解费用尚待核实的前提下决定是否提交。 |
| D-08 | 维修申请关联具体设备。针对具体预览明确确认、后端校验、幂等写入后才建单。创建成功后可凭工单号查询「待受理」记录。 | 主流程在建单可查处验收。普通聊天不能触发不可逆写入。 |
| D-09 | 同一预览连点、并发确认或超时重试，均只创建一单且返回同一工单号。 | 首次响应丢失也能取回原结果。 |
| D-10 | 同一设备最多一张待受理工单。在新会话中报告另一故障时，展示已有工单并提供转人工。 | 同一订单的其他设备仍可独立报修。 |
| D-11 | 报告「正在冒烟」时停止自查、提示停止使用并自动转人工。摘要保留危险征兆及已知故障码。 | 即使尚未确定型号也可转接。 |
| D-12 | 只提供对应型号说明书明确允许的用户自查步骤，标注出处并每次给一步。已恢复就结束；步骤无效或需专业检修时提供报修入口。 | 用户反馈决定下一轮诊断动作。 |
| D-13 | 分别表达设备保修状态与维修工单状态。 | 同一设备可同时处于保修「待核验」和维修工单「待受理」。 |
| D-14 | Grill-Me 访谈结束，PRD 完成后停在独立评审环节。 | 非关键问题作为评审假设，技术实现与异常细节留给后续 Spec 和测试设计；业务实现需另获授权。 |
