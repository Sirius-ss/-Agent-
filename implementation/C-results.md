# Phase C 验收记录

## 双端实时联动

`verify_isolated.py C` 运行通过。测试使用两个独立 Edge 配置、两端生产构建、隔离 PostgreSQL 和 Redis，用户端使用 DEMO 消费者，管理端使用客服小周。

1. 用户发送「洗衣机 E3」，选择 DEMO-W1-1 并提交一次「未恢复」。
2. 用户发送「设备正在冒烟」。管理端在刷新前收到同一 conversation_id 的 handoff_update，并显示接入队列。
3. 管理端查看 W-DEMO、故障码 E3、用户描述、已反馈步骤、冒烟风险和维修记录栏，然后接入会话。用户端实时切换成「人工服务中」。
4. 分别主动关闭两端连接。两端都完成重连，每端仅有一个打开的 WebSocket。随后分别整页刷新，客服重新打开会话可继续回复，用户侧恢复冒烟消息和历史。
5. 客服发送 DEMO 回复，用户端无需刷新即可收到，随后客服结束服务，用户端恢复「AI 客服」。用户端观测到 HUMAN 事件先于 AI 恢复事件。
6. 校验事件 conversation_id、页面消息 ID 唯一性和跨场景隔离。转到电商会话时看不到人工回复，切回家电会话后可回看。

## 项目运行与演示

按 README.md 准备本地 PostgreSQL、Redis 和各服务的 `.env`，依次运行三个服务的迁移，启动电商 8001、客服 8000、AI 8002，以及用户端 5183 和管理端 5184。

1. 用户端打开 `/mall`，从 DEMO 家电进入咨询，或在 `/chat` 查询「我的订单什么时候发货？」。
2. 在普通客服输入「我的洗衣机显示 E3，需要检修」，通过 JEV 引导进入家电售后。也可直接打开 `/appliance`。
3. 选择 DEMO-W1-1，核对说明书型号与页码。每步选择「未恢复」，打开维修预览，核对保修和费用待确认提示，明确确认后到「我的维修工单」查看。
4. 回到该家电会话发送「设备正在冒烟」。打开管理端并切换至客服小周，查看交接卡、接入、回复并结束服务。在用户端观察实时状态变化，刷新确认历史保留。

隔离验收命令为 `python verify_isolated.py A2`、`python verify_isolated.py C` 与 `python verify_isolated.py secondary`。测试使用端口 18100–18102、Redis 56379 的 14 号库及临时 PostgreSQL 数据库。浏览器测试额外使用 5173–5174，可用 `TEST_BROWSER` 指定 Edge 路径。第二家供应商配置读取 AI 服务本地 `.env` 中的 `SECONDARY_LLM_BASE_URL`、`SECONDARY_LLM_MODEL`、`SECONDARY_LLM_API_KEY`；验收进程单独使用这些设置。
